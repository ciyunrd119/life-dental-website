# 牙醫知識舊站文章搬運設計

## 目標

將 https://www.gracelife.com.tw/know.html 中本專案尚未收錄的牙醫知識文章與圖片搬入現有靜態網站，加入 knowledge.html 文章清單，並保留現有新版文章與元件語法。內容與圖片權利已由網站擁有者確認。

## 現況與範圍

- 舊站清單約有 74 筆文章，範圍橫跨 2015–2026 年。
- 本機 knowledge/ 已有 12 篇新版文章，其中部分是舊站主題的新版改寫。
- 本次搬運舊站中缺少的文章；相同或已有新版替代的主題不重複建立。
- 不重寫醫療內容，僅做必要的 HTML 結構轉換、編碼正規化、相對路徑調整與明顯錯字修正。
- 沿用現有 know-* 元件，不新增可重複使用的元件語法，因此原則上不修改 element.html。

## 來源盤點與去重

1. 從 know.html 擷取每筆文章的標題、日期與所有候選連結。
2. 依序以下列信號判定是否已存在：
   - 明確的來源日期與主題對應。
   - 標題主題、核心內文與主圖是否已有新版文章。
   - 本機文章中的來源圖片或獨有案例是否一致。
3. 若舊文章已有新版，保留新版，不再新增舊文章卡。
4. 同日多篇文章以來源檔名與標題區分，不只依日期去重。

## 來源連結錯誤處理

舊站清單存在標題連結與圖片連結不同、缺少副檔名、日期打錯與指向其他文章的情況。處理規則如下：

1. 優先嘗試與該筆日期對應的 know_YYYYMMDD.html。
2. 若清單提供多個候選連結，開啟後核對頁面主標與清單標題。
3. 若頁面轉向或內容不符，不從錯誤頁面搬運。
4. 所有可合理推定的候選網址均無法取得時，記錄為「來源無法取得」，不建立空白文章。

## 檔案與 URL 設計

- 搬運頁保留舊站檔名，放在 knowledge/，例如 knowledge/know_20180731.html。
- 這能避免大量人工英文 slug 命名造成錯誤，並保留來源的日期識別。
- 含中文或特殊檔名的來源頁改為可預測的 ASCII 檔名，例如 knowledge/know_cold-light-whitening.html。
- 文章內的首頁、服務頁、醫師頁與預約連結改為新站相對路徑。

## 圖片處理

- 每篇文章圖片儲存至 knowledge/img/<YYYYMMDD>/。
- 保留來源圖片的順序、圖說與內文位置。
- 正規化查詢字串、空白與重複檔名；不改變圖片內容。
- 圖片必須實際下載到本機，文章不保留對舊站圖片的熱連結。
- 無法取得的圖片會記錄在報告中，並在文章中移除該破圖，不放置假圖。
- 圖片 alt 優先沿用原始替代文字；空白時依附近段落與文章標題補上簡短描述。

## 文章頁轉換

- 以現有 knowledge/*.html 文章頁為殼層：網站頁首、麵包屑、文章 hero、文章內容、預約 CTA 與頁尾。
- 舊站文章主體轉成語意化的 h2、h3、p、ul、ol、figure，並放入 know-article-body。
- 舊站的導覽、側邊欄、廣告、Facebook 區塊、頁尾與重複診所資訊不搬入文章主體。
- 文章日期以來源清單日期為主；頁面內文有更明確日期時以內文為準。
- 保留醫師署名、案例描述、注意事項、表格與圖說。
- 移除舊站專用的 inline script、追蹤碼與舊 CSS class。

## knowledge.html 整合

- 每篇成功搬運的文章新增一張 knowledge-card。
- 按文章日期由新到舊排序，現有文章也一併依日期排序。
- 卡片使用文章第一張有效圖片作為封面；無圖文章使用現有牙醫知識預設視覺。
- 卡片摘要從首個有意義段落擷取，不自動截斷 HTML 標籤。
- 分類依文章主題對應到現有的 all-on-4、prosthodontics、implant、ortho、esthetic、periodontal、general。
- 單篇可有多個 data-knowledge-category，卡片顯示主分類標籤。

## 搬運工具

新增可重複執行的本機搬運腳本，負責：

1. 擷取來源清單與文章頁。
2. 檢查 HTTP 狀態、標題對應與重複主題。
3. 下載並改寫圖片路徑。
4. 產生新站文章頁與卡片資料。
5. 產生搬運報告，列出新增、跳過、修正連結、失敗頁面與失敗圖片。

腳本必須具備冪等性：重複執行不會複製卡片、文章或圖片。如果目標檔已存在且不是本腳本產生，應停止並報告，不覆寫人工編輯內容。

## 驗證與驗收

### 自動測試

- 先寫失敗測試，確認搬運腳本對去重、連結修復、圖片路徑與卡片排序的行為。
- 每張 knowledge-card 的 href 必須存在對應檔案。
- 每張卡片與文章主體的本機圖片必須存在。
- 不得保留對舊站圖片的 HTTP(S) 熱連結。
- knowledge.html 文章卡必須由新到舊排序，且沒有重複 href。
- 來源無法取得的文章必須出現在搬運報告，不能靜默略過。

### 結構與視覺驗證

- 執行現有 Ruby 測試、JavaScript 語法檢查與 git diff --check。
- 啟動本機靜態網站，檢查 knowledge.html 與代表性文章頁。
- 桌機與手機檢查卡片、圖片、長標題、表格與清單不產生水平溢位。
- 檢查篩選按鈕對所有分類有效。
- 檢查所有新文章的主要圖片可載入，無 404 或舊站熱連結。

## 完成條件

- 所有可取得且未被新版替代的舊站文章已搬入。
- 文字、圖片、署名與圖說與來源一致。
- knowledge.html 卡片可正確開啟內部文章，分類與日期順序正確。
- 搬運報告完整列出成功、跳過與失敗項目。
- 自動測試、Vercel production build 與桌機／手機視覺驗證全部通過。
